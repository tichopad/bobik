# Linux sandbox deployment

Gate a deployment with `BOBIK_REQUIRE_SANDBOX=1 go test -run '^TestBubblewrap$' -v ./internal/sandbox`, as the service user and under the same security policy as Bobik. Normal tests skip the successful-isolation cases if preflight cannot start, but still check that the production launcher fails closed. `sandbox.Preflight` runs the same runtime smoke test without reading notes.

- Install a maintained, non-setuid Bubblewrap with `--json-status-fd` and `--disable-userns`, util-linux `prlimit`, and distro builds of Bash, ripgrep (`rg`), grep, coreutils and sed. The package checks `/usr/bin` and `/bin`, not `PATH`. Runtime executables and their ELF dependencies are individually mounted read-only. Nonstandard library paths and executables with custom runtime search paths are unsupported.
- Bubblewrap must be allowed to create user, mount, PID, network, IPC and UTS namespaces, set up private loopback (`RTM_NEWADDR` and `RTM_NEWLINK`), and disable nested user namespaces. The kernel must accept the seccomp filter. On the Ubuntu host used to develop this package, Bubblewrap 0.9.0 failed at `loopback: Failed RTM_NEWADDR: Operation not permitted`, with AppArmor unprivileged user-namespace restrictions enabled. Current upstream still configures loopback when asked for a private network namespace and has no documented skip flag. Use a host policy that permits this profile; do not share the host network or run Bash directly.
- Give the deployment a hard cgroup v2 memory and process budget (`memory.max` and `pids.max`), sized for Bobik and its sandbox descendants together. The wall deadline and inherited per-process limits do not bound aggregate memory or process count. The implementation does not create or configure cgroups.
- Set `TMPDIR` to a trusted disk-backed directory. A search stages up to 10,000 files and 10,000 parent directories, 32 MiB per file and 256 MiB total. If anything cannot be read or copied within the budgets, the shell does not start. The call deadline is 30 seconds including staging, subject to the source and local filesystem returning control. Output is retained separately up to 64 KiB per stream and continues to drain after truncation.
- The shell sees a read-only copy under `/notes`, not a snapshot of concurrently changing live files. No writable filesystem scratch, host home, procfs, or host socket is mounted. Excluding `.gitignore` or other ignore files may change ripgrep results. For shell features needing `/dev/fd`, use ordinary pipelines instead.
