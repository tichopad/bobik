# Linux sandbox deployment

Run `BOBIK_REQUIRE_SANDBOX=1 go test -v ./internal/sandbox` and `bobik check-sandbox` as the deployment user under its actual security policy. The normal test suite skips successful-isolation tests when preflight cannot run. Preflight uses a disposable temporary vault, not your notes.

- Use maintained, non-setuid Bubblewrap with `--bind-fd`, `--ro-bind-fd`, `--block-fd`, `--json-status-fd`, and `--disable-userns`. Install distro Bash and util-linux `prlimit`. The runtime supports Linux amd64 and arm64 with `openat2` (Linux 5.6 or later). It uses read-only `/bin`, `/usr/bin`, `/lib`, `/usr/lib`, `/lib64`, and `/usr/lib64` where present; optional utilities come from those directories. No host environment, `/usr/local`, home, linker cache, or procfs is exposed to Bash.
- Bubblewrap needs private user, mount, PID, network, IPC and UTS namespaces. It must be allowed to configure loopback in its private network namespace and disable further user namespaces. Bobik itself must be able to read the child's `/proc/<pid>/mountinfo` and access its `/proc/<pid>/root` before releasing the command. The deployed security policy may refuse one or more of these operations. There is no host-network or unsandboxed fallback.
- `/notes` is the live vault; writes can be partial even on cancellation. Files under hide mounts are not accessible. A read-only mount prevents writes and replacements. Pin prevents replacement of the entry but does not make contents read-only. Protecting a nested path also pins its ancestors, which creates mount boundaries: `rename(2)` across those boundaries fails. The caller supplies an existing hide rule for `.agent-bobik`.
- Recursive host submounts are rejected, and the sandbox verifies the final mount table, including that no mounts propagate host changes. Vault and runtime binds must be on supported local filesystems such as ext4, btrfs, XFS, tmpfs, or overlayfs. Before Bash runs, a metadata-only scan rejects accessible symlinks, hardlinked regular files, devices, sockets, and FIFOs; hidden subtrees are skipped. The scan is linear in vault entries, not file bytes, and can dominate a small call on a slow Pi or a large vault. Bash cannot create filesystem links or special nodes.
- An advisory vault-directory lock serializes Bash calls on the same vault. Host editors and sync clients do not take this lock. They must not introduce symlinks, hardlinks, special files, or submounts, or relocate/replace protected paths during a call. A startup scan and recheck cannot enforce these rules against concurrent host changes. Do not reuse the same tree as overlapping vaults or expose credentials within read-only runtime directories or their aliases.
- A call has a 30-second wall timeout (including setup and metadata scan), a 30-second per-process CPU limit, a 32 MiB file-growth limit, bounded address space and descriptors, no core dumps, and up to 64 KiB captured per output stream. The command travels through a pipe, not process arguments. Arguments that Bash passes to individual utilities may still be visible to host observers. Blocking storage operations can delay return. Use a deployment cgroup with `memory.max` and `pids.max`, and give the vault a disk and inode quota if aggregate writes need bounding.
