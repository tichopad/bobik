# Codex on Linux: Bubblewrap lessons for Bobik

Source review of [Codex `main` at `1c0c806`](https://github.com/openai/codex/commit/1c0c806028d5d585c574f85e5c8e979dbb2205be) (2026-11-20), not a runtime test.

- **Ubuntu 24.04 / AppArmor.** Ubuntu's default policy can allow unprivileged user namespace creation but deny subsequent capabilities inside it. Codex probes system `bwrap` with `--unshare-user --unshare-net --ro-bind / / /bin/true` and treats known stderr, including `Failed RTM_NEWADDR` or `RTM_NEWLINK`, as a startup warning—not proof of AppArmor or a successful isolation test. OpenAI recommends loading the scoped `bwrap-userns-restrict` extra profile on 24.04 if needed. Bobik should keep its kernel-log hint and run `bobik check-sandbox` as the deployment user rather than recommend turning off the host-wide restriction. [Ubuntu release notes](https://discourse.ubuntu.com/t/ubuntu-24-04-lts-noble-numbat-release-notes/39890#p-99950-unprivileged-user-namespace-restrictions-15) · [OpenAI setup docs](https://developers.openai.com/codex/sandboxing#prerequisites) · [Codex probe](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/sandboxing/src/bwrap.rs#L22-L166)

- **Mount propagation.** Vendored `bwrap` makes `/` recursively slave (`MS_SLAVE | MS_REC`), not recursively private; the later `rprivate` operation targets the discarded old root. On a host with shared mounts, sandbox binds can therefore show `master:` and receive host mount events without sending them back. Bubblewrap explicitly notes that its recursive remount flags do not apply to mounts propagated later. Bobik's [final mount check](../internal/sandbox/topology_linux.go) rejects `shared:`, `master:`, and `propagate_from:`. Keep that check; improve the diagnostic and investigate launching from a deployment-scoped private mount namespace rather than accepting inbound propagation. [Bubblewrap setup](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/vendor/bubblewrap/bubblewrap.c#L3325-L3333) · [Old-root cleanup](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/vendor/bubblewrap/bubblewrap.c#L3429-L3436) · [Remount caveat](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/vendor/bubblewrap/bind-mount.c#L449-L473) · [Linux mount semantics](https://www.kernel.org/doc/html/latest/filesystems/sharedsubtree.html#detailed-semantics)

- **Networking.** Codex's Bubblewrap path unshares user and normally PID namespaces. Restricted networking adds `--unshare-net` and seccomp; managed proxy also uses a private network namespace but bridges to configured proxy endpoints. Full network access does not request a new network namespace. Transparent TCP is a separate opt-in with distro Bubblewrap and TUN requirements. None of those online modes is a fallback for Bobik's offline shell. [Codex network selection](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/linux-sandbox/src/linux_run_main.rs#L543-L554) · [Sandbox README](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/linux-sandbox/README.md#L16-L38) · [Namespace and seccomp details](https://github.com/openai/codex/blob/1c0c806028d5d585c574f85e5c8e979dbb2205be/codex-rs/linux-sandbox/README.md#L90-L140)

- **Launcher and fallback UX.** Codex prefers an eligible distro binary, skipping candidates under the working directory or modifiable through sandbox-allowed writes. It checks flag support; missing `--argv0` has a compatibility path, while a missing or unsupported system launcher can select the bundled binary. The namespace probe warns; it does not trigger a switch. Separately, a known fresh `/proc` mount failure can retain inherited `/proc` while keeping PID isolation (not for transparent TCP with PID isolation). Landlock is legacy, not an automatic fallback, and is rejected for filesystem-restricted execution. Bobik can borrow actionable, distinct diagnostics without loosening enforcement.
